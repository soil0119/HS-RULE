# HS-RULE PDF RAG 및 UI Implementation Plan

> **인계 상태:** 사용자 최신 요청으로 RAG·LangChain은 `sumiiniee` 담당(#9, #10, #11)으로 분리했다. 이 계획의 RAG 구현은 더 진행하지 않는다. 기존 PDF 색인 초안은 Draft PR #2에 인계하며, 앱/API/UI/도메인은 #6, #7, #8에서 별도 main 기반 PR로 진행한다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development task-by-task. 각 구현자는 하위 에이전트를 만들지 않는다. 구현은 한 작업씩, 독립 리뷰 후 다음 작업으로 진행한다.

**Goal:** 사용자 제공 PDF를 페이지 근거가 있는 규정 지식으로 색인하고, LangChain RAG·안전한 API와 PC/모바일 UI를 제공한다.

**Architecture:** PDF 원본은 로컬 업로드 디렉터리에 보관하고 PostgreSQL/pgvector에 문서·페이지·청크를 저장한다. MiniLM·Groq와 LangChain의 검색·프롬프트·구조화 응답을 사용한다. UI는 Local Codex로 생성한 HTML/CSS/JS를 FastAPI에 연결한다.

**Tech Stack:** Python 3.11, FastAPI, psycopg2, PostgreSQL/pgvector, pdfminer.six, sentence-transformers, langchain-core, langchain-groq, HTML/CSS/JS.

**Spec:** [프로젝트 진단과 고도화안](../../project-diagnosis.md). 사용자 최종 선택: 규정 입력은 PDF, UI는 PC·모바일 / 전체 메뉴 / 서비스 수준, 서비스 주소는 `https://hs.officeworkkt.com`. UI·LangChain RAG·핵심 API 실제 구현과 회귀 검증을 승인했고, 기능별 잦은 커밋과 분리된 PR을 요청했다.

## Global Constraints

- 기존 사용자 작업, 원본 ZIP과 크롤러 참고 자료를 임의 삭제하지 않는다. 실행 데이터에 기존 메뉴 껍데기 JSON을 사용하지 않는다.
- 실제 PDF는 아직 전달되지 않았다. 실제 Groq 키도 없다. 테스트용 PDF·외부 의존성 대역 검증과 실제 규정·Groq 검증을 구분한다.
- 사용자 PDF·DB·모델 캐시·비밀값을 Git에 넣지 않는다. 원본 ZIP의 세션 쿠키는 사용하거나 외부로 전달하지 않는다.
- 공식 규정 PDF는 명시적 `public` 분류로 색인한다. 관리자 업로드 기본값은 `private`이며 공개 질의에서 제외한다.
- 미설정 관리자 비밀번호·서명키에서 관리자 로그인을 허용하지 않는다. UI 열람은 모델·DB 초기화 실패로 막지 않는다.
- 페이지는 1부터 센다. 전문은 보존하고 임베딩 입력은 실제 토크나이저의 128토큰 한도를 지킨다.
- 기존 `rule_chunks`를 자동 삭제하거나 레거시 데이터로 폴백하지 않는다. 새 문서 스키마를 명시적으로 초기화한다.
- `hs.officeworkkt.com`은 설정 목표다. 실제 DNS·TLS·배포 완료는 검증 없이 주장하지 않는다.
- PR은 사용자 머지로 남긴다. 각 단계는 지정 파일만 커밋하고 테스트 근거를 남긴다.

## Review Focus

- 텍스트가 없는 스캔 PDF와 빈 페이지를 정상 색인으로 오인하지 않는가: 문서 전체 텍스트 없음 거부, 빈 페이지 경고·부분 범위 공개.
- 청크의 페이지·본문·ID·토큰 한도와 사용자에게 보여주는 근거가 일치하는가: 다중 페이지·한국어 헤더·장문 회귀 검사.
- DB 삽입·재색인 실패가 기존 문서와 비공개 자료를 손상하지 않는가: 트랜잭션 롤백과 원본 보존 검증.
- 공개 검색·목록·원본 다운로드에서 비공개 문서가 제외되는가: 쿼리 필터와 HTTP 권한 검사.
- 외부 모델의 임의 인용·깨진 JSON·오류가 정상 답변이나 충돌 없음으로 표시되지 않는가: 후보 ID 검증·오류 상태·UI 안전 렌더링.

## 공통 데이터 계약

`hsrule/` 패키지를 사용한다. 한 문서 dict는 다음 필드를 갖는다.

- `id`: 서버 발급 UUID hex 또는 동등한 안전한 불투명 ID.
- `title`, `filename`, `visibility` (`public`/`private`), `content_hash` (SHA-256), `page_count`, `pages`.
- `pages`: `[{page_number: int, text: str}]`; 빈 페이지도 기록한다.
- `chunks`: `[{id: str, ordinal: int, page_start: int, page_end: int, article: str, content: str, embedding_text: str}]`.
- `warnings`: 텍스트 없는 페이지 등 사람이 이해할 수 있는 처리 제한 목록.
- 문서 목록 응답에 본문 전체를 포함하지 않는다. 출처 URL은 `/documents/{id}/file#page={page_start}`로 서버가 구성한다.

`hsrule.repository.RegulationRepository(database_url: str)`의 공개 메서드:

- `initialize() -> None`: 문서·청크 스키마를 만들며 기존 `rule_chunks`는 건드리지 않는다.
- `health() -> dict`: 문서·청크 수와 준비 상태. DB 오류는 상위 호출자가 503으로 변환한다.
- `save_document(document: dict, embeddings: list[list[float]]) -> dict`: 문서의 `chunks`와 임베딩 개수가 일치해야 하며 한 트랜잭션으로 저장한다. 중복 SHA-256은 명확한 충돌 오류다.
- `list_documents(include_private: bool = False) -> list[dict]`.
- `get_document(document_id: str, include_private: bool = False) -> dict | None`.
- `delete_document(document_id: str) -> dict | None`: 문서 및 청크 삭제. 파일 삭제는 API 서비스가 안전한 ID 경로에서 수행한다.
- `vector_candidates(embedding: list[float], include_private: bool = False, limit: int = 20) -> list[dict]`.
- `keyword_candidates(query: str, embedding: list[float], include_private: bool = False, limit: int = 20) -> list[dict]`.
- 검색 후보 공통 필드: `id`(청크 ID), `document_id`, `title`, `article`, `content`, `page_start`, `page_end`, `score`(실제 코사인), `visibility`. 순위는 각 검색 방식의 반환 순서다.

`hsrule.rag.RagService(repository, embedder, chat_model)`의 계약:

- `answer(question: str, history: list[dict], include_private: bool = False) -> dict`: `answer`, `sources`, `found`, `followups`, 선택 `dept`, `dept_phone`. 출처에 `id`, `document_id`, `page_start`, `page_end`, `title`, `article`, `url`, 실제 `score`를 포함한다.
- `analyze_conflict(text: str, filename: str, include_private: bool = True) -> dict`: 타입 검증한 기존 충돌 응답과 분석 범위/부분 처리 상태.
- 외부 실패와 인용 검증 실패는 정상 결과로 폴백하지 않는다. 서버용 의미 있는 예외 타입과 오류 코드를 문서화한다.

## Task 1 — PDF 수집·문서 저장 기반 / PR A
