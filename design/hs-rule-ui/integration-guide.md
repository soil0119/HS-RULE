# HS-RULE 프런트엔드 인계 · 전면 재설계

## 실행 구조

빌드·React·외부 CDN 의존성이 없는 HTML/CSS/JavaScript입니다. 백엔드·DB·RAG·임베딩·벡터·모델 코드는 변경하지 않았으며 이 프로젝트에 포함하지 않습니다.

| 파일 | 화면·역할 | 서비스 경로 |
| --- | --- | --- |
| `index.html` | 질문, 대화 이력 패널, PDF 규정 목록 | `/`, `/#library` |
| `login.html` | 관리자 로그인 | `/login-page` |
| `upload.html` | PDF 저장, 공개 범위, 원본 열람, 삭제, 충돌 검토 | `/upload` |
| `styles.css` | SUIT 폰트 로드, 공통 토큰, 데스크톱·휴대폰 스타일 | 상대 경로 |
| `i18n.js` | 한국어·영어 UI 및 설정 저장 | 상대 경로 |
| `api.js` | 동일 출처 API 계약 및 파일 검증 | 상대 경로 |
| `app.js` | 안전한 DOM 렌더링과 화면 흐름 | 상대 경로 |
| `icons.svg` | 로컬 선형 SVG 아이콘 | 상대 경로 |
| `fonts/` | 실제 SUIT Variable, OFL 라이선스, 출처·해시 기록 | 상대 경로 |

기존 FastAPI의 화면 경로는 그대로 사용합니다. `.html` 파일 경로에서는 파일 간 상대 링크를 사용하고, 서비스 경로에서는 `/`, `/#library`, `/login-page`, `/upload`를 사용합니다. CSS·JS·아이콘·`fonts/`는 HTML과 같은 기준 디렉터리에 제공하세요. 정적 자산을 `/static/` 아래에 둘 경우 HTML의 `href`/`src`, SVG `use`, CSS의 폰트 상대 경로를 함께 조정해야 합니다. 실제 대학 로고는 새로 만들어 대체하지 않았습니다.

`archive/`는 재설계 전 복사본입니다. 실행·배포 대상이 아니며 현재 화면에서 참조하지 않습니다.

## 서체·시각 시스템

사용자 지정 방향에 따라 흰색·중립 회색·거의 검정인 글자·학술적 파랑을 사용했습니다. 고정 사이드바·홍보 슬로건·큰 빈 카드·분할 마케팅 로그인 화면을 제거했습니다. 본문 16px, 화면 제목 25–27px, 구역 제목 18px, 메타데이터 12–14px입니다.

SUIT Variable은 [공식 저장소](https://github.com/sun-typeface/SUIT)의 공식 2.x 웹폰트 경로에서 내려받아 `fonts/SUIT-Variable.woff2`로 저장했습니다. `@font-face`에 `font-weight: 100 900`을 선언하고 한글·영문·폼 컨트롤 전체에 적용했습니다. 세 화면 모두 같은 로컬 파일을 preload합니다. 라이선스 전문은 `fonts/OFL-1.1.txt`, 다운로드 출처·가변 축·SHA-256은 `fonts/source.json`입니다. 운영 중 원격 폰트 요청은 없습니다.

화면은 FontFaceSet으로 실제 로드 결과를 검사해 `html[data-font-state]`를 `loading`/`loaded`/`unavailable`로 기록합니다. 사용자용 디버그 패널은 없습니다. 서버에서 파일을 제공할 때 WOFF2의 Content-Type과 정적 경로를 유지하세요.

## 한영 전환과 개인화

- 기본 언어는 한국어입니다. 상단 오른쪽의 한국어/EN 설정으로 전환하며 `html.lang`과 페이지 제목도 갱신합니다. 휴대폰에서는 같은 설정이 상단 메뉴에 있습니다.
- 탐색, 레이블, placeholder, 접근성 레이블, 도움말, 빈 상태, 대기·오류 상태, 업로드·삭제 대화상자는 모두 번역합니다.
- 실제 PDF 제목·파일명·분류·원문, 실제 질문·답변·후속 질문, 분석 결과 내용은 원래 언어로 유지합니다. 서버가 제공하는 자유 형식의 문서 안내도 원문을 보존합니다. 알려진 상태·오류 코드는 로컬 UI 문구로 표시합니다.
- `hsu_language` (`ko`/`en`)와 `hsu_audience` (`student`/`staff`)가 페이지 간 유지됩니다. 대상 선택은 예시와 입력 힌트만 바꾸며 권한 판정에는 사용하지 않습니다.
- 질문 언어는 요청 시점에 캡처합니다. 요청 후 UI 언어를 바꾸어도 이미 반환된 답변을 번역하거나 다시 요청하지 않습니다. 실제 답변 번역은 외부 RAG 팀의 책임입니다.

## API 계약

모든 API는 동일 출처 경로만 호출합니다. 관리자 요청은 실제 로그인 응답의 `token`을 `hsu_token`에 저장해 Bearer 헤더로 전달합니다. 비밀번호를 저장하거나 미리 입력하지 않습니다.

| 기능 | 요청·처리 |
| --- | --- |
| 질문 | `POST /query` JSON `{question,messages,language}`. 질문은 공백 제거 후 최대 2,000자. 실제 이전 대화의 `user`/`assistant`만 최대 12개 전달하며 현재 질문은 이력에 중복 삽입하지 않습니다. |
| 공개 PDF 목록 | `GET /rules` → `{chapters:[{chapter,rules:[metadata]}],total}`. 개수는 실제 수신한 표시 가능한 문서에서 계산합니다. `total`만으로 전체 수록이나 준비 완료를 주장하지 않습니다. 장별 필터는 데이터가 2개 분류 이상일 때만 표시합니다. |
| 로그인 | `POST /login` JSON `{username,password}` → `{success:true,token}`. 성공 후 허용된 내부 목적지로만 이동합니다. |
| 관리자 목록 | `GET /uploaded-rules` → `{rules:[metadata]}`. 첫 실제 성공 응답으로 세션을 확인하고 문서 관리 기능을 활성화합니다. |
| PDF 등록 | `POST /upload-regulation`, multipart `file`, `title`(선택), `visibility`(`private` 기본값 또는 `public`). 여러 파일을 순차 처리합니다. 여러 파일일 때 별도 제목은 생략합니다. |
| 삭제 | `DELETE /uploaded-rules/{id}`. 32자 문서 ID만 사용합니다. 파일명을 확인하는 대화상자에서 승인한 뒤 요청합니다. JSON 성공 또는 HTTP 204를 처리합니다. 파일명 기반 삭제 요청은 없습니다. |
| 원본 | `GET /documents/{id}/file`. 공개 문서는 인증 없이 요청합니다. 비공개 문서는 Bearer로 fetch한 뒤 Blob URL로 열며 토큰을 URL에 넣지 않습니다. 출처에 공개 범위가 없을 때는 로그인 중인 세션으로 요청합니다. |
| 충돌 검토 | `POST /conflict/`, multipart `file`, `language`. 관리자 요청이며 외부 분석에 위임합니다. 저장 기능과 독립된 대기·실패·미연결·결과 상태를 표시합니다. |
| 내보내기 | `POST /export/pdf`, `/export/docx` JSON `{title,content,sources,question}`. 실제 답변과 유효한 PDF 페이지 근거가 있을 때만 활성화합니다. 바이너리의 기본 서명도 확인한 뒤 다운로드합니다. |

문서 metadata: `{id,name,title,filename,page_count,visibility,warnings,status,index_status,url}`. `status:'stored'`는 **원본 저장됨**, `index_status:'not_connected'`는 **답변 검색 연결 전**으로 표시합니다. 누락되거나 알 수 없는 상태를 준비 완료로 추정하지 않습니다.

질문 출처: `{document_id,page_start,page_end,title,url,chunk_id?,score?}`. 실제 PDF 페이지 또는 범위를 인용합니다. `page_end`가 없으면 시작 페이지 한 쪽으로 표시합니다. 유효한 페이지나 원본 경로가 없으면 확인된 근거로 취급하지 않습니다. 점수는 표시하지 않으며 실제 출처 메타데이터에만 보존합니다. 조문 번호를 만들어 넣지 않습니다.

## PDF 등록·원본 열람

프런트엔드는 `.pdf` 확장자, 허용 MIME, 0바이트 여부, 20 MiB 경계, PDF 헤더를 기본 검사합니다. 이 검사는 PDF 전체의 구조·안전성 검증을 대신하지 않으며 서버에서 최종 검증해야 합니다.

실제 전송 바이트로 진행률을 표시합니다. 전송 100%는 ‘저장 확인 중’이며 성공을 뜻하지 않습니다. 서버가 `{success:true,document:{id,status:'stored',…}}`를 반환한 뒤에만 ‘원본 저장됨’으로 표시합니다. 등록 후 실제 문서 목록을 다시 조회합니다. 색인 완료를 표시하는 경로는 없습니다. 실패한 파일만 재시도합니다.

32자 ID는 영문·숫자·`_`·`-`로 검증합니다. 서버가 다른 ID 형식을 사용한다면 `api.js`의 `validId`를 해당 계약에 맞춰 변경하세요. ID나 확인할 파일명이 없으면 삭제를 비활성화합니다.

비공개 원본의 브라우저 새 탭에는 인증 헤더를 직접 붙일 수 없으므로 먼저 인증 fetch를 수행하고 Blob을 엽니다. 팝업이 차단되면 다운로드로 대체합니다. 알려진 공개 문서에는 저장된 토큰을 보내지 않아 오래된 세션이 공개 열람을 막지 않도록 했습니다.

## 오류·보안·독립성

서버 오류의 `{code,request_id}`를 받아 번역된 안내와 문의 번호를 표시합니다. 내부 예외·서버 명령·제공자 설정을 UI에 노출하지 않습니다. 다음 코드와 HTTP 상태를 별도로 처리합니다.

| 조건 | UI 동작 |
| --- | --- |
| `rag_not_connected`, HTTP 503 | ‘답변 서비스가 아직 연결되지 않았습니다.’ 목록·원본·관리 기능을 함께 잠그지 않습니다. 충돌 검토에서는 분석 서비스 미연결로 구분합니다. |
| `admin_not_configured` 및 호환 코드 | 관리자 로그인 미설정 안내 |
| `invalid_credentials` / 로그인 HTTP 401 | 계정 정보 확인 안내 |
| 만료·잘못된 세션 / 관리자 HTTP 401 | 토큰 제거, 재로그인 안내, 관리 기능 잠금 |
| `forbidden` / HTTP 403 | 권한 없음 안내, 관리 기능 잠금 |
| `duplicate_pdf`·`duplicate_document` / 업로드 HTTP 409 | 기존 PDF 중복 안내 |
| `file_too_large` / HTTP 413 | 20 MiB 제한 안내 |
| `invalid_pdf` 및 호환 코드 / HTTP 415·422 | 유효한 PDF 선택 안내 |
| 연결 실패·잘못된 응답·시간 초과 | 서로 구분된 안내와 재시도 경로 |

공식 코드명이 추가되거나 달라지면 `app.js`의 `errorKey` 매핑을 갱신하면 됩니다. 빈 충돌 목록은 ‘충돌 없음 보장’으로 표현하지 않습니다. 예시 AI 답변·가짜 PDF·가짜 규정·고정 개수·과거 자료 진단 경고는 기본 UI에 없습니다.

동적 내용은 DOM과 `textContent`로 렌더링합니다. 제한된 제목·굵은 글씨·목록만 요소로 구성하며 서버 HTML은 해석하지 않습니다. 원문 링크는 HTTP(S)만 허용하고 새 창은 opener를 차단합니다. 외부 원문 URL에 인증 헤더를 보내지 않습니다.

## 접근성·반응형·저장

상단 탐색, 레이블이 있는 폼, 44px 기본 조작 영역, 가시적인 포커스, 네이티브 모달의 포커스·Escape 동작을 제공합니다. 휴대폰은 두 줄의 간결한 헤더와 상단 설정 메뉴, 한 열의 작업 공간, 읽을 수 있는 문서 행으로 바뀝니다. 데스크톱의 PDF 근거는 오른쪽에, 좁은 화면에서는 답변 아래에 배치됩니다.

한글 조합 중 Enter 전송을 막습니다. 일반 키보드는 Enter 전송·Shift+Enter 줄바꿈, 터치 환경은 Enter 줄바꿈·Ctrl/⌘+Enter 전송을 지원합니다. Ctrl/⌘+K는 새 질문입니다. `scrollIntoView`는 사용하지 않습니다.

대화 이력은 `hsu_conversations_v2`와 `hsu_active_v2`에 저장합니다. UI 언어나 오류 문구를 대화 이력으로 전송하지 않습니다. 기존 `hsu_conversations`는 예전 조문 기반 출처와 혼합하지 않도록 자동으로 가져오지 않습니다. 언어·대상 설정은 별도이며 로그아웃 후에도 유지합니다.

## 검증 범위

HTML 구조·로컬 의존성·중복 ID·JavaScript 문법·번역 키를 검사합니다. 모의 API와 DOM 모델로 한국어·영어, 10개 폭의 화면 부트스트랩과 설정 접근, 질문 이력·인용·예외, PDF 제한·권한·전송률·ID 삭제·원본 인증·충돌·내보내기 계약을 검증합니다. DOM 모델 검증은 실제 브라우저 레이아웃 검증과 구분합니다.

로컬 폰트 바이너리의 가변 축(100–900), 한글·영문 글리프, 라이선스와 해시를 확인했습니다. 실제 FastAPI 서버의 CORS 없는 동일 출처 제공, 정적 파일 경로·권한 정책·최종 PDF 검증·다운로드 응답은 연동 환경에서 확인할 항목입니다.

선택적 회귀 검증은 프로젝트 루트에서 `node qa/verify.cjs`로 실행합니다(Node 20+ 및 Python 3, 제품 런타임에는 불필요). 모의 API/DOM·번역 키 검증 575개 항목이 통과했습니다. `qa/viewport-review.html`은 실제 프로젝트를 1440px 한국어·390px 영어로 나란히 열고, 각 화면의 폰트 요청·FontFaceSet 상태·가로 넘침을 표시하는 별도 검토 페이지입니다. 제품 탐색에는 포함하지 않습니다. 실브라우저 픽셀 배치·실기기 입력·실제 서버 응답에 대한 검증은 별도로 남겨 둡니다.
